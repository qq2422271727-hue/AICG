# ASHWAKE 起步接触实验室 v0.1.1

这是可独立导入的原创骨架动作实验项目，**不是 ASHWAKE v0.8.1 主游戏升级，不含完整关卡，也不是 APK**。从旧版动作实验室复制后，仅修改“地面静止→起跑”的初始脚步相位；稳定版本、GitHub 主工程与 v0.8.1 检查点均未覆盖。

## 手机上试用：三步

1. 把 ZIP 解压到一个新的独立文件夹，不要解压覆盖现有 ASHWAKE 工程。
2. 在 Godot 4.7.2 Android 编辑器的项目列表中，导入该文件夹里的 `project.godot`。渲染器为 Compatibility，横屏，主场景为 `lab.tscn`。
3. 运行项目，按屏幕 `LEFT` / `RIGHT` 启动行走，观察最初的支撑脚；`JUMP` 跳跃、`HIT` 挥剑。先停稳再左右起步各一次即可。

桌面键位：A/D 或方向键移动，空格/W/上键跳跃，J/X 攻击，F1 骨架显示，R 重置。没有本地 Godot 运行时，本次未验证编辑器导入或设备运行；若编辑器报错，以实际输出为准。

## 本次改了什么

旧逻辑每次起跑固定 `phase=0`。它会把原来的足底从 −6 px 缓慢拖到 +15.12 px；第一帧只移动约 1.11 px，所以原先“首帧小于 2 px”的检查没发现整个过渡期的 21.12 px 滑脚。

新逻辑 `locomotion_rig_2d.gd::_grounded_start_phase()` 从上一帧**实际绘制、经 IK 求解后的足底**计算相位，选择还有较长支撑时间的脚，保留它的世界空间接触点。左右方向使用同一公式。

未改移动速度、步幅、跳跃、骨长、攻击挂点、剑光、相机、按钮与 UI 比例。新函数不接管首次落地；找不到合法支撑足时保留旧相位回退。停步过渡中立即重启、斜坡和移动平台的视觉效果不在本次验收范围。

## 文件与来源

- `project.godot` / `lab.tscn`：独立实验入口。
- `locomotion_rig_2d.gd`：唯一玩法修复文件；`evidence/start_contact.patch` 为相对旧实验室的精确差异。

- `evidence/`：检查结果与边界说明；`RELEASE_MANIFEST.json`：版本及验证状态。
